# Completion conditions

All scoped requirements and success/failure/boundary scenarios verified; callers migrated; no current-change placeholders; meaningful tests and applicable local Gate pass; BFS impact review complete. Run name preflight before strict validation and archive. No Gate FAIL or unresolved REVIEW_REQUIRED. Record exact failures and remaining actions. No runtime/deployment claims from documentation or scaffold builds.

Each completed OpenSpec spec/change requires exactly two commits: first the implementation/tests/archive commit, then a HANDOFF.md-only pointer/evidence commit.

Both commits are required for completed implementation; do not request conversational confirmation when authorized. Stop after the HANDOFF-only commit. No push. Exactly one active current_spec; remove when no active work remains.

Publication requires full LICENSE, chosen visibility, credential-safe metadata, verified remote and explicit publication scope. Documentation UI evidence requires a real screenshot and revision-bound capture plan; unavailable UI/capture is recorded, not fabricated.

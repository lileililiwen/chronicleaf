Repository Chronicleaf only. Primary boundary src/Chronicleaf.Application/Milestones/; domain types in Core, exported service contracts in Application, DbContext configurations/migrations in Infrastructure/Persistence, route mapping in Api, optional UI at src/Chronicleaf.Web/src/features/projects-and-milestones/. Inspect the explicit symbols below; create only modules needed for this outcome. Dependencies: community-persistence, community-access. Each dependency owns its contracts; do not implement an uncompleted dependency inside this package. Preserve forge.yaml, .standard receipts, unrelated files and current_spec.

C# net10.0 / ASP.NET Core 10 for Api/Application/Infrastructure/integrations; React + TypeScript + Vite for src/Chronicleaf.Web. PostgreSQL is the single relational store; Hangfire jobs run in application process. Test projects tests/Chronicleaf.Unit.Tests, Chronicleaf.Integration.Tests (real disposable PostgreSQL), and Chronicleaf.Api.Tests (WebApplicationFactory); browser tests under src/Chronicleaf.Web/tests. Interfaces live in Chronicleaf.Application, domain records in Core, IO adapters in the named integration/Infrastructure project, DI in Api/Program.cs. Consumers never reference sibling source directories. Native dependencies pinned in project lockfiles during implementation; no package install or runtime provider call in this authoring task.

**Keep local.** Chronicleaf domain/workflow lifecycle and user review are product-specific; no matching recurring implementation is evidenced in sibling platform contracts. Reuse dependency-owned access/jobs/storage contracts, never duplicate those concerns. Evidence inspected: dotnet-platform-libs/README.md lists Platform.Jobs and Platform.Storage families but no Milestone/narrative/voice/content/publisher workflow. No shared `/lib` added and no sibling edit authorized.

## Contract and compatibility decisions
Consume the common contracts owned by dependency packages: UUID ids, UTC ISO8601 timestamps, camelCase JSON, owner/scope lookup and optimistic bigint revision. Private routes use community-access owner sessions; Hosted activates cloud-tenant-boundary, then team-project-permissions gates reads/edits/approval/publishing. Absent Hosted packages does not silently enable tenancy. Unknown or foreign-scoped resource is 404; unauthenticated private request 401, insufficient permission 403; malformed JSON400, semantic validation422, missing required If-Match428, stale revision409, oversized payload413, transient dependency503, timeout504. Error envelope is {code,message,traceId,fieldErrors?}; message never includes provider raw bodies, tokens or absolute host paths. The persistence package owns serialization/error middleware; feature-specific error codes named below extend it without changing envelope. Every mutation audits ids/action/revision, not secret/evidence plaintext. List endpoints default25/max100 with scope-bound opaque cursor when applicable. Bound input limits and deterministic empty/missing states appear below.

Core/Project.cs(id,scopeId,name,description,repoConnectionId nullable,projectUrl nullable,revision,archivedAt) and Milestone.cs(id,projectId,title,version nullable,occurredAt UTC,type,source,sourceKey nullable,status candidate|confirmed|dismissed,revision,notes,knownLimitations[],nextSteps[]). Infrastructure owns projects/milestones migrations; unique(project_id,source,source_key) when nonnull. Api routes /api/projects CRUD; /api/projects/{id}/milestones GET/POST; /api/milestones/{id} GET/PATCH; POST /confirm or /dismiss. POST returns 201/Location; list cursor limit 1..100 default 25, order occurredAt desc,id desc. React Projects, Dashboard, MilestoneEditor actual persisted records.

## Behavioral model and invariants
Manual creation defaults confirmed after explicit save action; imports always candidate. Confirm/dismiss idempotent for same revision/status; dismissed → confirmed requires owner action. Request PATCH requires If-Match revision (missing 428, stale 409); archived project read-only. Types include feature/release/deployment/ui/bugfix/performance/payment/feedback/stars/migration/open-source/first-customer/custom. UUID scoped lookups return 404. Title 1..160, notes 20k chars; URL http/https stored but not fetched here; version free label ≤80.

## Failure, boundary and rollback policy
Invalid values 422; duplicate source candidate returns existing id; concurrent edits cannot overwrite. Delete is soft archive preserving related evidence/assets; hard erase belongs retention package. Empty dashboard shows create-project action, not generated sample history. AI cannot confirm, dismiss or modify fields.

For new tables use a uniquely named forward EF migration plus schema integration test. Additive changes must preserve preexisting scope/revisions; a required nonnull column is backfilled before enforcement. No destructive rollback by ordinary startup. If this package owns no table (pure renderer/adapter/query), migration is N/A and verify existing schema unchanged. Rollback disables only this feature's registration/configuration and preserves stored evidence/assets/receipts; upstream publication and previously exported bytes are never assumed reversible. Partial IO result state must follow the owning jobs/media/publisher contract, not be called success. Scope/time/revision checks happen again at result commit.

## Verification oracle
DB/API/browser: create real project and manual milestone, import duplicate candidate, confirm manually, concurrent PATCH one wins, archive makes edits 409, empty dashboard shows truthful state and persisted milestone remains after restart.

Create ProjectsAndMilestonesTests in the relevant test project; seed scope A/B, deterministic UUIDs and injected UTC clock where data/state is involved. Assert externally observable response/record/hash/side effects for each scenario, not private implementation structure. Commands: `dotnet build Chronicleaf.sln --nologo`; `dotnet test Chronicleaf.sln --filter FullyQualifiedName~ProjectsAndMilestonesTests`; frontend UI changes additionally `npm --prefix src/Chronicleaf.Web ci`, `npm --prefix src/Chronicleaf.Web run build`, `npm --prefix src/Chronicleaf.Web run test:e2e -- tests/projects-and-milestones.spec.ts`. Required DB/browser/provider fixture services must actually run; unavailable dependency is a failure to record, not a passing mock runtime claim. Configure test projects and native scripts in dependency foundation packages before feature execution. Apply any configured local Gate, then names/strict validation/diff checks.

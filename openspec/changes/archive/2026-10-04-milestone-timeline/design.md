# Design: Private chronological project timeline

## Context and implementation boundary
Repository Chronicleaf only. Primary boundary src/Chronicleaf.Web/Timeline/; domain types in Core, exported service contracts in Application, DbContext configurations/migrations in Infrastructure/Persistence, route mapping in Api, optional UI at src/Chronicleaf.Web/src/features/milestone-timeline/. Inspect the explicit symbols below; create only modules needed for this outcome. Dependencies: projects-and-milestones. Each dependency owns its contracts; do not implement an uncompleted dependency inside this package. Preserve forge.yaml, .standard receipts, unrelated files and current_spec.

## Language, ownership and release
C# net10.0 / ASP.NET Core 10 for Api/Application/Infrastructure/integrations; React + TypeScript + Vite for src/Chronicleaf.Web. PostgreSQL is the single relational store; Hangfire jobs run in application process. Test projects tests/Chronicleaf.Unit.Tests, Chronicleaf.Integration.Tests (real disposable PostgreSQL), and Chronicleaf.Api.Tests (WebApplicationFactory); browser tests under src/Chronicleaf.Web/tests. Interfaces live in Chronicleaf.Application, domain records in Core, IO adapters in the named integration/Infrastructure project, DI in Api/Program.cs. Consumers never reference sibling source directories. Native dependencies pinned in project lockfiles during implementation; no package install or runtime provider call in this authoring task.

**Keep local.** Chronicleaf domain/workflow lifecycle and user review are product-specific; no matching recurring implementation is evidenced in sibling platform contracts. Reuse dependency-owned access/jobs/storage contracts, never duplicate those concerns. Evidence inspected: dotnet-platform-libs/README.md lists Platform.Jobs and Platform.Storage families but no Milestone/narrative/voice/content/publisher workflow. No shared `/lib` added and no sibling edit authorized.

## Contract and compatibility decisions
Consume the common contracts owned by dependency packages: UUID ids, UTC ISO8601 timestamps, camelCase JSON, owner/scope lookup and optimistic bigint revision. Private routes use community-access owner sessions; Hosted activates cloud-tenant-boundary, then team-project-permissions gates reads/edits/approval/publishing. Absent Hosted packages does not silently enable tenancy. Unknown or foreign-scoped resource is 404; unauthenticated private request 401, insufficient permission 403; malformed JSON400, semantic validation422, missing required If-Match428, stale revision409, oversized payload413, transient dependency503, timeout504. Error envelope is {code,message,traceId,fieldErrors?}; message never includes provider raw bodies, tokens or absolute host paths. The persistence package owns serialization/error middleware; feature-specific error codes named below extend it without changing envelope. Every mutation audits ids/action/revision, not secret/evidence plaintext. List endpoints default25/max100 with scope-bound opaque cursor when applicable. Bound input limits and deterministic empty/missing states appear below.

GET /api/projects/{id}/timeline?cursor&limit&includeCandidates=false → {items:[id,title,version,occurredAt,type,status],nextCursor}. Stable order occurredAt asc,id asc with opaque versioned cursor encoding the pair and project scope; limit 1..100 default 25. Application/Timeline/TimelineQuery.cs reads milestone contract only; no duplicate timeline table. React ProjectTimeline.tsx supports milestones, date groups, empty state and navigation to editor; user timezone display defaults browser locale, API UTC.

## Behavioral model and invariants
Default timeline shows confirmed records only. Owner may toggle candidate visibility, visually labeled candidate; dismissed omitted. Cursor bound to query filter/project to prevent cross-project reuse. Project Journey is a separate opt-in projection; this endpoint always private. Backdated edits alter chronology on next fresh query; cursor documents snapshot-not-guaranteed refresh notice.

## Failure, boundary and rollback policy
Foreign/missing project 404; malformed cursor/filter 422; no records yields []/null. Same timestamp ordered UUID; archived project readable. No inferred achievements/traffic/stars without milestone records. Avoid external image requests in this package.

For new tables use a uniquely named forward EF migration plus schema integration test. Additive changes must preserve preexisting scope/revisions; a required nonnull column is backfilled before enforcement. No destructive rollback by ordinary startup. If this package owns no table (pure renderer/adapter/query), migration is N/A and verify existing schema unchanged. Rollback disables only this feature's registration/configuration and preserves stored evidence/assets/receipts; upstream publication and previously exported bytes are never assumed reversible. Partial IO result state must follow the owning jobs/media/publisher contract, not be called success. Scope/time/revision checks happen again at result commit.

## Verification oracle
API cursor fixture: 52 confirmed and 3 candidates across equal timestamps and two projects; concatenate pages without duplicates, toggle candidates, foreign cursor fails. Browser empty/backdated/timezone states and editor navigation checked.

Create MilestoneTimelineTests in the relevant test project; seed scope A/B, deterministic UUIDs and injected UTC clock where data/state is involved. Assert externally observable response/record/hash/side effects for each scenario, not private implementation structure. Commands: `dotnet build Chronicleaf.sln --nologo`; `dotnet test Chronicleaf.sln --filter FullyQualifiedName~MilestoneTimelineTests`; frontend UI changes additionally `npm --prefix src/Chronicleaf.Web ci`, `npm --prefix src/Chronicleaf.Web run build`, `npm --prefix src/Chronicleaf.Web run test:e2e -- tests/milestone-timeline.spec.ts`. Required DB/browser/provider fixture services must actually run; unavailable dependency is a failure to record, not a passing mock runtime claim. Configure test projects and native scripts in dependency foundation packages before feature execution. Apply any configured local Gate, then names/strict validation/diff checks.

## Decision ledger and activation gates
Phase: MVP. No unresolved product-policy decision in this scoped contract. Demand-gated packages require recorded demand before activation; Cloud packages do not become Community dependencies unless explicitly indicated for optional tenant-safe extension. Native third-party versions are lockfile implementation inputs, verified against .NET10/toolchain and fixtures, not an invitation to redesign contracts. External artifact/credential/network absence is recorded as prerequisite unavailability; never fabricate success.

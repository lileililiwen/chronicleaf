## Contract and compatibility decisions
Consume the common contracts owned by dependency packages: UUID ids, UTC ISO8601 timestamps, camelCase JSON, owner/scope lookup and optimistic bigint revision. Private routes use community-access owner sessions; Hosted activates cloud-tenant-boundary, then team-project-permissions gates reads/edits/approval/publishing. Absent Hosted packages does not silently enable tenancy. Unknown or foreign-scoped resource is 404; unauthenticated private request 401, insufficient permission 403; malformed JSON400, semantic validation422, missing required If-Match428, stale revision409, oversized payload413, transient dependency503, timeout504. Error envelope is {code,message,traceId,fieldErrors?}; message never includes provider raw bodies, tokens or absolute host paths. The persistence package owns serialization/error middleware; feature-specific error codes named below extend it without changing envelope. Every mutation audits ids/action/revision, not secret/evidence plaintext. List endpoints default25/max100 with scope-bound opaque cursor when applicable. Bound input limits and deterministic empty/missing states appear below.

Application/Content/ReviewService.cs; PATCH /api/assets/{id} {expectedRevision,bodyMarkdown,title} creates revision; POST /api/assets/{id}/approve {contentRevision,evidenceRevision,voiceFindingsAcknowledged:false} → approval{id,actorId,contentHash,evidenceRevision,approvedAt}; POST /unapprove; GET /api/assets/{id}/export?format=markdown&revision returns owner-private UTF-8 attachment only for valid approval. React MarkdownEditor+sanitized Preview, grounding findings, approve and ExportPreview; no Notion or rich editor. Use safe Markdown parser with raw HTML disabled and link protocols http/https only. ContentAsset status draft|approved|invalidated; published receipts separate.

### Approval schema and visual extension point
This package creates approvals(id,asset_id,content_revision,actor_id,body_hash,evidence_revision,voice_snapshot_hash,media_selection_hash,artifact_hash nullable,approved_at,invalidated_at,reason). Asset payload kind text|structured|visual and immutable revision payload hash is the common approval extension point; MVP implements text only. Derivative/export packages must bind their structured JSON or visual checksum through this same service and cannot inherit source approval. If current voice validation returns blocking findings they must be corrected; no silent acknowledgment bypass.

## Behavioral model and invariants
Approve under transaction lock verifies content hash, latest bundle revision and zero blocking deterministic voice/grounding findings. Editing body/title/screenshot caption/selection/evidence creates new revision or invalidation, never mutate approved snapshot. EvidenceChanged outbox plus synchronous export revalidation prevents asynchronous gap. Export uses approved immutable revision + relative media paths in optional ZIP; plain .md includes clearly identified screenshot references, no absolute host path or private credentials. Default export target format Markdown; no upstream publication calls.

## Failure, boundary and rollback policy
Missing/stale approval 409 approval_required|approval_stale; stale edit409; empty body422; unsafe markup remains inert in browser. User retains access to prior draft even if provider unavailable. Concurrent approval/edit cannot export edited unreviewed version. Maximum100KiB Markdown; explicit approval button never triggered by Enter in editor.

For new tables use a uniquely named forward EF migration plus schema integration test. Additive changes must preserve preexisting scope/revisions; a required nonnull column is backfilled before enforcement. No destructive rollback by ordinary startup. If this package owns no table (pure renderer/adapter/query), migration is N/A and verify existing schema unchanged. Rollback disables only this feature's registration/configuration and preserves stored evidence/assets/receipts; upstream publication and previously exported bytes are never assumed reversible. Partial IO result state must follow the owning jobs/media/publisher contract, not be called success. Scope/time/revision checks happen again at result commit.

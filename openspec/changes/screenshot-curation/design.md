## Contract and compatibility decisions
Consume the common contracts owned by dependency packages: UUID ids, UTC ISO8601 timestamps, camelCase JSON, owner/scope lookup and optimistic bigint revision. Private routes use community-access owner sessions; Hosted activates cloud-tenant-boundary, then team-project-permissions gates reads/edits/approval/publishing. Absent Hosted packages does not silently enable tenancy. Unknown or foreign-scoped resource is 404; unauthenticated private request 401, insufficient permission 403; malformed JSON400, semantic validation422, missing required If-Match428, stale revision409, oversized payload413, transient dependency503, timeout504. Error envelope is {code,message,traceId,fieldErrors?}; message never includes provider raw bodies, tokens or absolute host paths. The persistence package owns serialization/error middleware; feature-specific error codes named below extend it without changing envelope. Every mutation audits ids/action/revision, not secret/evidence plaintext. List endpoints default25/max100 with scope-bound opaque cursor when applicable. Bound input limits and deterministic empty/missing states appear below.

Consume Core/ScreenshotCandidate.cs and screenshot_candidates table owned by screenshot-capture; extend its existing candidate|selected|rejected transition service and one-primary database index, without a second candidate schema. GET /api/milestones/{id}/screenshots; PATCH /api/screenshots/{id} {caption,status,isPrimary,expectedRevision}; POST /api/milestones/{id}/screenshots/order {ids,expectedBundleRevision}. Application service appends screenshot EvidenceItem only after selection; unselect creates superseding bundle without erasing prior referenced history. ScreenshotPicker.tsx provides preview, select/reject, primary choice, ordering and captions.

## Behavioral model and invariants
Unique partial index one primary per milestone; make-primary atomically clears previous primary. Require selected status before primary. Caption ≤1000 chars treated plain text; ordering must contain exactly current selected ids, no duplicates. Owner can reject a bad candidate; physical deletion obeys media_in_use. Compare previous screenshot is explicit milestone/media selection, not assumed version equivalence.

## Failure, boundary and rollback policy
Foreign screenshot 404, stale screenshot or bundle revision 409, rejected primary 422. Capture re-run never replaces human selection automatically. UI image errors show unavailable candidate. Rejection does not purge evidence used by approved historical content; preserve tombstones.

For new tables use a uniquely named forward EF migration plus schema integration test. Additive changes must preserve preexisting scope/revisions; a required nonnull column is backfilled before enforcement. No destructive rollback by ordinary startup. If this package owns no table (pure renderer/adapter/query), migration is N/A and verify existing schema unchanged. Rollback disables only this feature's registration/configuration and preserves stored evidence/assets/receipts; upstream publication and previously exported bytes are never assumed reversible. Partial IO result state must follow the owning jobs/media/publisher contract, not be called success. Scope/time/revision checks happen again at result commit.

## Verification oracle
DB/browser fixture select A/B, switch primary concurrently, reject unused C, edit caption and reorder; verify immutable new bundle and prior media retained, one primary, cross-project ids rejected and no spontaneous selection after new captures.

Create ScreenshotCurationTests in the relevant test project; seed scope A/B, deterministic UUIDs and injected UTC clock where data/state is involved. Assert externally observable response/record/hash/side effects for each scenario, not private implementation structure. Commands: `dotnet build Chronicleaf.sln --nologo`; `dotnet test Chronicleaf.sln --filter FullyQualifiedName~ScreenshotCurationTests`; frontend UI changes additionally `npm --prefix src/Chronicleaf.Web ci`, `npm --prefix src/Chronicleaf.Web run build`, `npm --prefix src/Chronicleaf.Web run test:e2e -- tests/screenshot-curation.spec.ts`. Required DB/browser/provider fixture services must actually run; unavailable dependency is a failure to record, not a passing mock runtime claim. Configure test projects and native scripts in dependency foundation packages before feature execution. Apply any configured local Gate, then names/strict validation/diff checks.

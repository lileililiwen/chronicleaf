# Chronicleaf delivery roadmap and package map

The complete requirement.md remains the product baseline. Fifty-two changes are implemented, verified and archived: `community-foundation`, `community-persistence`, `community-access`, `projects-and-milestones`, `background-jobs`, `local-media-storage`, `platform-jobs-adoption`, `milestone-evidence`, `credential-vault`, `voice-profiles`, `llm-provider-contract`, `github-evidence`, `screenshot-capture`, `llm-openai-adapter`, `grounded-markdown-drafts`, `screenshot-curation`, `milestone-timeline`, `llm-gemini-adapter`, `llm-anthropic-adapter`, `llm-openrouter-adapter`, `llm-ollama-adapter`, `markdown-review-export`, `community-compose-release` (MVP and MVP-RELEASE, rows marked IMPLEMENTED below, with their canonical specs in `openspec/specs/`), plus the POST-MVP, CLOUD and DEMAND-GATED follow-ups `local-git-evidence`, `github-release-candidates`, `github-graphql-enrichment`, `narrative-memory`, `html-content-export`, `content-asset-variants`, `screenshot-evolution-images`, `static-blog-export`, `public-project-journey`, `agency-client-projects`, `cloud-tenant-boundary`, `team-project-permissions`, `cloud-object-storage`, `scheduled-project-sync`, `hosted-archive-operations`, `github-app-connection`, `linkedin-copy-package`, `medium-import-package`, `publisher-contract`, `publisher-github-pages-adapter`, `publisher-devto-adapter`, `publisher-hashnode-adapter`, `publisher-ghost-adapter`, `publisher-wordpress-adapter`, `publisher-custom-blog-adapter`, `evolution-gif-export`, `xiaohongshu-content-package`, `video-story-scripts` and `agency-weekly-reports`. Every dependency-ordered package is therefore done except the two owner-BLOCKED changes `semantic-narrative-retrieval` and `hosted-managed-ai`, which stay active and held with their material decisions unresolved. No `current_spec` remains. Each change owns one independently testable outcome; the held changes' dependencies do not erase their blockers. Community MVP GitHub → confirmed Milestone → screenshot → grounded Markdown → human edit/approval → export plus private Timeline is implemented, with all five BYOK adapters delivered, six publishing adapters on the publisher contract, and the release package verifying restore-identical evidence; `deployable` stays `false` (no browser-confinement sandbox on this host, no live provider smoke).

## Phase policy

- **MVP**: portable Community application and first complete workflow, no automated publishing, no videos, no multi-tenant Cloud.
- **MVP-RELEASE**: real two-service install, restore and complete workflow evidence; repository publication remains separate explicit action.
- **POST-MVP**: fuller Community evidence, history, content and static outputs; does not expand the MVP release gate.
- **DEMAND-GATED**: specified extensions; activation depends on recorded user demand. This is a roadmap priority gate, not an implementation authorization.
- **CLOUD**: optional Hosted capabilities, separate identity/isolation/ops; Community does not depend on Cloud. Site-local end-user login is distinct from workspace manager/operator auth.

Blocked packages below state unresolved material decisions. Their dependencies do not erase blockers. Published Platform.* artifact availability is checked at adoption time; no personal-checkout dependency or sibling edits are authorized.

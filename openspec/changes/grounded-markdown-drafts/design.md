## Contract and compatibility decisions
Consume the common contracts owned by dependency packages: UUID ids, UTC ISO8601 timestamps, camelCase JSON, owner/scope lookup and optimistic bigint revision. Private routes use community-access owner sessions; Hosted activates cloud-tenant-boundary, then team-project-permissions gates reads/edits/approval/publishing. Absent Hosted packages does not silently enable tenancy. Unknown or foreign-scoped resource is 404; unauthenticated private request 401, insufficient permission 403; malformed JSON400, semantic validation422, missing required If-Match428, stale revision409, oversized payload413, transient dependency503, timeout504. Error envelope is {code,message,traceId,fieldErrors?}; message never includes provider raw bodies, tokens or absolute host paths. The persistence package owns serialization/error middleware; feature-specific error codes named below extend it without changing envelope. Every mutation audits ids/action/revision, not secret/evidence plaintext. List endpoints default25/max100 with scope-bound opaque cursor when applicable. Bound input limits and deterministic empty/missing states appear below.

Core/ContentAsset.cs and ContentRevision.cs, tables content_assets(id,scope_id,project_id,milestone_id,type,status,current_revision) and content_revisions(asset_id,revision,evidence_bundle_id,voice_snapshot jsonb,summary jsonb,body_markdown,body_hash,created_at). POST /api/milestones/{id}/drafts {providerId,model,evidenceRevision,voiceRevision,consentHash,idempotencyKey} returns202 operationId; GET /api/assets/{id} returns current draft and grounding findings. Confirmed milestone required. Phase1 provider returns strict JSON: milestone_title,summary,changes[],problems_solved[],known_limitations[],next_steps[]; each factual array item {text,evidenceIds[]}. JSON schema rejects extra keys, null required fields, ids outside snapshot, arrays>100 and strings>8000 chars.

### Initial content schema ownership
Initial asset type is markdown-story; this package creates ContentAsset and ContentRevision tables with default status draft. Review package adds approval table rather than retroactively treating generated rows as approved. Approval entity stores sourceRevision,bodyHash,evidenceRevision,voiceSnapshotHash,mediaSelectionHash; voice profile updates alone do not edit old drafts, but review validator always checks the frozen effective profile tied to that draft. Core factual source ids are GUIDs from EvidenceBundle items, not arbitrary URL strings. Missing narrative integration yields empty history context rather than invented prior story.

## Behavioral model and invariants
Phase2 generates Markdown using only accepted summary and immutable input ids, then validates citations in internal claim map; Markdown may carry footnote ids or internal provenance metadata but raw secrets never. Provider output and imported text are untrusted, raw HTML disabled in preview. Unsupported factual claim fails grounding review; local rule verifies evidence-id membership, human preview flags semantic claims requiring judgment. No claim of perfect automated factual verification. Record prompt/schema version. Empty evidence requires manual notes before generation; all known limitations retained. Result committed as draft, never approved.

## Failure, boundary and rollback policy
Invalid JSON gets at most one repair call with same provider and consented snapshot, charge warning shown; then failed invalid_summary. Unsupported references fail immediately. Stale evidence or voice during processing supersedes result; prior asset remains. Limit Markdown 100KiB; refusal preserves previous draft. No marketing statistics/star/user counts invented.

For new tables use a uniquely named forward EF migration plus schema integration test. Additive changes must preserve preexisting scope/revisions; a required nonnull column is backfilled before enforcement. No destructive rollback by ordinary startup. If this package owns no table (pure renderer/adapter/query), migration is N/A and verify existing schema unchanged. Rollback disables only this feature's registration/configuration and preserves stored evidence/assets/receipts; upstream publication and previously exported bytes are never assumed reversible. Partial IO result state must follow the owning jobs/media/publisher contract, not be called success. Scope/time/revision checks happen again at result commit.

## Verification oracle
Fake provider first/second response fixtures include foreign evidence id, injection text, malformed JSON, ignored known limitation and unsupported user count. Assert repair cap, failure without overwriting, draft-only status and exact provenance. Browser preview loads real generated fixture asset, not provider simulation in production.

Create GroundedMarkdownDraftsTests in the relevant test project; seed scope A/B, deterministic UUIDs and injected UTC clock where data/state is involved. Assert externally observable response/record/hash/side effects for each scenario, not private implementation structure. Commands: `dotnet build Chronicleaf.sln --nologo`; `dotnet test Chronicleaf.sln --filter FullyQualifiedName~GroundedMarkdownDraftsTests`; frontend UI changes additionally `npm --prefix src/Chronicleaf.Web ci`, `npm --prefix src/Chronicleaf.Web run build`, `npm --prefix src/Chronicleaf.Web run test:e2e -- tests/grounded-markdown-drafts.spec.ts`. Required DB/browser/provider fixture services must actually run; unavailable dependency is a failure to record, not a passing mock runtime claim. Configure test projects and native scripts in dependency foundation packages before feature execution. Apply any configured local Gate, then names/strict validation/diff checks.
